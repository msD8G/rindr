# Szenen-Zustand, Speichern/Laden, Assets, Rückgängig

`scene-state.js`, `assets.js`, `history.js`, Teile von `viewer.js`.

- `src/scripts/history.js` – Rückgängig/Wiederholen (Strg+Z, Strg+Y / Strg+Umschalt+Z, Knöpfe im GUI-Ordner „Szene“), max. 50 Schritte. Aktionen tragen sich *nach* dem Ausführen mit `record({ label, undo, redo, mergeKey? })` ein; gleicher `mergeKey` innerhalb 1 s = ein Schritt (Schieberegler), `transaction()` bündelt (Bibliotheks-Material anlegen + zuweisen). Erfasst: Verschieben/Drehen (Gizmo-Drag = 1 Schritt, Event `edit` im Transformer), Sichtbarkeit (`onVisibilityEdit`), Material zuweisen (`assignMaterial` in viewer.js, über Mesh-Index → übersteht Neu-Tessellieren), Material-Parameter/Node-Graph/Umbenennen/Anlegen/Löschen/Import (in `MaterialManager`, `history` gesetzt), Licht/Umgebung/HDRI/Bildwinkel/Schnittebene (`_tracked` in properties.js). Nicht erfasst: Kamerabewegung, Pathtracing-/Qualitäts-Einstellungen. Stapel wird bei neuem Modell und „Szene laden“ geleert; Strg+Z in Text-/Zahlenfeldern bleibt beim Feld.
- Szenen-Rundlauf geprüft (Scratchpad `roundtrip2.mjs`: Einstellungen ändern → speichern → Szene mit umbenanntem, fehlendem Modell öffnen → Datei verknüpfen → Zustand vergleichen: keine Abweichung). Dabei behoben: laufende Kamerafahrt vom Laden (fitCamera/frameObject eines Zusatzmodells) überschrieb die wiederhergestellte Kamera (`ctx.stopCameraMotion` vor dem Setzen); FSR-Schärfe über `pathTracing.sharpness` (Pathtracer wird erst nachgeladen).
- Szenen-Format v2 + Asset-Verwaltung (wie Verknüpfungen in InDesign, ohne „Szene verpacken“): `captureState` schreibt `version: 2`, `models[]` (je Modell `{ file, placement, count, transforms, hidden, deleted, assignments }`, Schlüssel ohne `x<id>:`-Präfix, Reihenfolge = `sceneIndex`), `assets` (Modelle, HDRI) und weiterhin `model` für ältere Leser; `sceneModels(state)` liest auch v1. `openSceneFile(state, files?)` in viewer.js: passen die geladenen Modelle → nur Zustand anwenden; sonst je Modell `resolveModelSource` (schon geladen > mitgegebene Dateien per Dateiname > Server `HEAD models/<name>`), erstes gefundenes = Hauptmodell, Rest per `addModel(src, { sceneIndex, placement })`, danach `restoreScene(state, { force: true })` + `checkAssets`. Fehlende Modelle: Platzhalter `kind: 'missing'` mit ⚠ im Scene Graph (Klick auf den Namen wählt aus: Eigenschaften-Panel mit „Verknüpfen…“ / „Aus der Szene entfernen“, Entf und Rechtsklick-Menü ebenso – `removeMissingModel`; nur Klick auf ⚠ (`data-action="warn"`, `onWarn`) öffnet das Asset-Fenster), ihr Zustand bleibt beim Speichern erhalten (`missingModels`, an alter Position). Modelle mit fehlenden Texturen bekommen ⚠ an der Modell-Zeile. Asset-Fenster `assets.js` (Knopf mit Ketten-Symbol in der Szene-Gruppe, gelb wenn etwas fehlt; öffnet sich beim Laden automatisch): Liste mit Status, „Verknüpfen…“, „Dateien…“/„Ordner…“, Dateien/Ordner auf das Fenster ziehen → Zuordnung über den Dateinamen; HDRI → `environment.selectFile`, Modelle/Texturen → aktueller Zustand wird erfasst und die Szene mit den neuen Dateien neu aufgebaut (`openSceneFile(…, { reload: true })` – ohne `reload` griff der Schnellweg „gleiche Modelle geladen“ und nachgereichte Texturen wurden nie geladen). `relinkFiles` ist serialisiert (`relinkChain`, wartet auch auf laufende Ladevorgänge – ein zweiter Drop während des Nachladens erfasste sonst eine halb geladene Szene) und meldet danach „n Dateien verknüpft“ bzw. abgelegte Dateien, die zu nichts Fehlendem passen (`status.relinked`/`relinkUnmatched`). Mehrere Dateien/Ordner auf einmal gehen. Drag nur mit Bildern (`isAssetDrag`: alle Einträge `image/*` – Namen gibt der Browser erst beim Drop heraus): fehlt etwas → Drop-Fläche „Fehlende Dateien verknüpfen“ (`setDropOverlay(true, 'relink')`, eine Zone), sonst keine Fläche (dropEffect none). Ordner/unbekannte Typen zeigen weiter Ersetzen/Hinzufügen; ein Drop ohne Modelldatei verknüpft trotzdem. Import-Materialien haben als Herkunft `import:<Dateiname>:<Nr.>` (vorher `import:<Nr.>` – Materialien verschiedener Modelle kollidierten: nach Ersetzen + Verknüpfen übernahmen die Materialien des neuen Modells Einstellungen/Graphen des alten → weiße Teile); `restore` ordnet jedes gespeicherte Material höchstens einem zu (gleiche Datei zweimal) und liest alte Szenen (`import:<Nr.>`) weiter. Scheitert das Laden eines neuen Hauptmodells, werden die Materialien des ersetzten Modells trotzdem entfernt (`pruneUnused` im catch von `loadModel`). Ist nach dem Verknüpfen nichts mehr offen, schließt sich das Asset-Fenster. Ist beim Verknüpfen noch kein Modell geladen (nur Platzhalter), wird die Kamera des erfassten Zustands verworfen – sonst stellte das Nachladen die Kamera der leeren Szene wieder her und das Modell lag außerhalb des Bildes. JSON + Modelle zusammen ins Fenster ziehen geht auch. Unvollständige glTF (nur `.gltf` abgelegt, `.bin` fehlt): `checkGltfFiles` in mesh-importer.js prüft vor dem Laden die externen Puffer → `MissingFilesError` mit allen fehlenden Dateien (Puffer + Bilder) → `registerIncomplete` in viewer.js: Platzhalter in `missingModels` mit `source` + `files`, Asset-Fenster listet .bin und Texturen; nachgereichte Dateien (aufs Asset-Fenster oder ins 3D-Fenster gezogen – Drop ohne Modelldatei bei fehlenden Assets = Verknüpfen) laden das Modell mit der gemerkten Quelle neu (`resolveModelSource`). Platzhalter werden über ihre Position in der Szene (`sceneIndex`) ersetzt, nicht über den Dateinamen (dieselbe Datei zweimal in einer Szene – vorher verdrängte der zweite unvollständige den ersten → nur ein Modell); aus einer Szene behalten sie ihren gespeicherten Zustand (`sceneChunks`). Wird beim Öffnen einer Szene gar kein Modell gefunden, wird der übrige Zustand trotzdem angewendet (`restoreScene(state, { force: true })`: Materialien, HDRI + Optionen, Lichter, Kamera, Pathtracing, Objektiv …; vorher nur Materialien, davor gar nichts) – sonst fehlten beim späteren Verknüpfen (Zustand wird neu erfasst) z.B. Bibliotheks-Materialien wie Gold und ihre Zuweisungen gingen verloren. Schlägt das Nachladen eines solchen Modells anders fehl, bleibt der Platzhalter (`source.incomplete` → `registerIncomplete`) – vorher verschwand das Modell und das Asset-Fenster war leer. Fehlende Emissive-Textur bei unbeleuchteten Materialien: `getDependency` liefert null → `collectUnlit` ohne Map (vorher „reading 'clone' of null“). Solange das Asset-Fenster offen ist, erscheint beim Datei-Drag keine Ersetzen/Hinzufügen-Fläche: das Fenster wird hervorgehoben (`setDragActive`) und ein Drop irgendwo im Viewer = Verknüpfen (`relinkFiles`).
