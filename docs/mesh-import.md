# Mesh-Import (glTF, FBX, STL, PLY)

`src/scripts/mesh-importer.js`, `mesh-orient.js`.

- `src/scripts/mesh-importer.js` – STL (binär + ASCII, `STLLoader`, nachgeladen wie die übrigen Loader; vorher `normalizeStl`: Der Loader erkennt Binär nur an Header-Anzahl = Dateilänge, sonst ASCII nur an „solid“ in den ersten 5 Bytes → ASCII mit Leerzeilen/ohne „solid“ oder Binär mit falscher Anzahl/angehängten Bytes ergab „Invalid typed array length“ bzw. 0 Dreiecke (Test-STL, Okt. 2026). Jetzt: Text → als ASCII mit ergänztem `solid`/`endsolid`, Binär → Kopie mit der Anzahl, die die Länge hergibt (Original-Puffer bleibt, ist evtl. Asset); Text ohne STL-Schlüsselwörter (z.B. als .stl gespeicherte HTML-Seite – enthält oft CSS „solid“) → Fehler `import.mesh.notStl`; Dreiecke mit NaN/Infinity werden verworfen (`dropBrokenTriangles`), 0 Dreiecke → `import.mesh.noFaces` statt leerem Modell; Prüfskript Scratchpad `stl-test.mjs`): Einheit mm (STL hat keine), Hochachse geraten (`meshUpAxis`, auch PLY; Okt. 2026 – vorher immer Z oben → Auto-STL lag auf der Seite): SolidWorks im Header → Y; sonst Bounding-Box: Modell steht auf seinem Boden (Minimum ≈ 0 auf genau einer der Achsen Y/Z) bzw. ist um 0 zentriert (diese Achse waagerecht); unentschieden Z; `?upAxis=y|z` übersteuert. Ausrichtung der Flächen (`mesh-orient.js`, Worker-Auftrag `orient` in eigenem Kurzzeit-Worker `orientTrianglesIsolated`): Punkte exakt verschweißt, Stücke = über konsistent geteilte Kanten verbundene Dreiecke; geschlossenes Stück mit deutlich negativem Volumen → umgedreht, offenes Stück (Blech) per Strahltest (Stichproben ∝ Fläche, Strahl entlang/gegen die Normale, beliebiger Treffer per `shapecast`; entkommt die Rückseite öfter → umgedreht, beide verdeckt = bleibt), Dreiecke mit gegenläufigem Zwilling (gewollt zweiseitig) nie. Auto-STL (1,3 Mio. Dreiecke): 8 138 Stücke / 29 399 Dreiecke gedreht, ~3,3 s; Kamerastrahlen von außen, die zuerst eine Rückseite treffen: 28,8 % → 1,0 % (Scratchpad `stl-view-check.mjs`). STL ist fertig trianguliert – keine Qualitätsstufe (nur Glättwinkel/Vereinfachen denkbar); Facetten-Normalen verworfen → `computeNormals` (30° Knickwinkel wie Blender – Nutzerwunsch Okt. 2026, bei 60° liefen ebene Flächen in angrenzende Schrägen hinein –, glatt statt facettiert; eigene Umsetzung mit Gewichtung nach Eckwinkel – vorher three `toCreasedNormals` ungewichtet: Fächer aus langen dünnen Dreiecken und schräg geteilte Vierecke zogen die Normalen schief, „verzerrte“ Schattierung bei Test-STL, Okt. 2026; Zylinder 24 Segmente: Fehler 2,5° → 0,01°, 1,2 Mio. Dreiecke 670 → 440 ms; Prüfskript Scratchpad `normals-test.mjs`; betrifft nur Mesh-Formate ohne Normalen, nicht STEP), ein Mesh mit Standard-Material; geprüft mit erzeugtem Zylinder. glTF/GLB (Draco, Meshopt, KTX2; Loader werden erst beim ersten glTF/FBX per dynamischem `import()` geladen (`loadLibs`, ~170 KB); Draco/Basis-Decoder referenziert three.js selbst per `new URL(…, import.meta.url)` → Vite legt sie gehasht in `_astro/` ab – die frühere Kopie in `public/decoders/` ist entfernt) und FBX. Wandelt in dieselbe Struktur wie der STEP-Import um (nodes/geometries/meshes, absolute Matrizen, eigene Puffer, BVH + Tangenten im STEP-Worker-Pool via `buildGeometryBVHs`). Einheiten → mm (glTF ×1000, FBX ×10·UnitScaleFactor). Multi-Material-Meshes: Gruppen mit gleichem Material werden zu einem Mesh zusammengefasst (Schlüssel = erste Gruppe; `extractGeometries`: ein Durchgang über den Index für alle Gruppen, jeder Quell-Punkt einmal berechnet, Skinning entfällt in der Grundpose – `inBindPose` prüft je Knochen bindMatrixInverse · Knochen-Welt · boneInverse · bindMatrix = Einheit; vorher je Gruppe ein Mesh und je Gruppe ein Lauf über alle Punkte – bei FBX mit zehntausenden Gruppen Minuten statt Sekunden; gespeicherte Zuweisungen an FBX mit mehreren Gruppen je Material treffen danach evtl. nicht mehr), Skinning/Morph als aktuelle Pose gebacken (Normalen mit denselben Knochen umgerechnet – `applyBoneTransform` auf Punkt und Punkt+Normale; vorher verworfen und je Dreieck neu berechnet → facettiert); fehlende Normalen: `computeNormals` (über Position verschweißt, 30° Knickwinkel, nach Eckwinkel gewichtet) statt flach je Dreieck, InstancedMesh aufgelöst. Abgelegte Dateien: fehlende Texturen werden gemeldet, nie vom Server nachgeladen; per `?model=` (auch mit Unterordner, z.B. `?model=ordner/scene.gltf`, Pfadteile einzeln kodiert) werden `.bin`/Texturen relativ zur Modell-URL geladen und nur bei Ladefehler (`manager.onError`) als fehlend gemeldet. Unbeleuchtete glTF-Materialien (`KHR_materials_unlit`, typisch Sketchfab mit eingebackenem Licht: Grundfarbe schwarz, Bild in der Emissive-Textur): GLTFLoader macht daraus `MeshBasicMaterial` ohne Emissive → `collectUnlit` liest Emissive-Textur/-Farbe/`KHR_materials_emissive_strength` aus dem JSON, `convertMaterial` macht ein schwarzes, nicht glänzendes, selbstleuchtendes Material (Emissive-Textur, sonst Farbtextur).
