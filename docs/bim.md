# IFC / BIM und BCF

`src/scripts/ifc/`, `src/scripts/bcf/`.

- IFC / BIM (`src/scripts/ifc/`, Okt. 2026): `.ifc` + `.ifczip` (erstes .ifc im Zip, `readZip` aus splat-formats.js) laufen als `type: 'mesh'` (`MESH_EXTENSIONS`), `importMeshFile` leitet an `importIfc` weiter (dynamischer Import). Geometrie per **web-ifc 0.0.78** (MPL-2.0, WebAssembly, exakt gepinnt) in `ifc-worker.js` (Worker ~385 KB + Wasm ~574 KB gzip, nur bei IFC geladen; einfädig): `StreamAllMeshes`, Geometrie je `geometryExpressID` geteilt, Meter + y oben → ×1000 in den Mesh-Matrizen, `COORDINATE_TO_ORIGIN` (georeferenziert), `CIRCLE_SEGMENTS` 24. Web-ifc liefert Klassennamen als „IfcWallStandardCase“ → im Worker überall `.toUpperCase()` (Schlüssel, i18n `bim.classes.*`). Baum: Projekt/Grundstück mit nur einem Kind übersprungen, Container ohne Geometrie darunter fallen weg (Räume ohne Möbel, Raster), Geschosse nach Höhe, in jedem Container Gruppen je Klasse („Wände (87)“, Varianten wie StandardCase zusammengefasst, `CLASS_GROUPS`), Elemente nach Name (Revit-ID „:12618181“ am Ende abgeschnitten), Elemente außerhalb der Struktur unter „Ohne Zuordnung“. Knoten tragen `ifc: { id, type, spatial | group, count }` → `group.userData.ifc`. Materialien je Stilname (IfcStyledItem → Oberflächenstil; Revit benennt nach Material, „<Unnamed>“ zählt nicht) sonst Bauteil-Material (IfcRelAssociatesMaterial: Schicht/Liste/Profil …) + Farbe; transparent oder „Glas“ → Transmission, Metallnamen → metallisch (`styleMaterial`); Herkunft `import:<Datei>:<Name|Farbe>`. Jede Geometrie eine eigene Instanz (dieselbe Geometrie kommt in einem Element mehrfach vor – `meshByKey` „Instanz:Geometrie“ hätte sie zusammengelegt), gezählt wird je Element (`countId`). Eigenschaften: Worker bleibt offen (`root.userData.bim`, `disposeRoot` beendet ihn), `ctx.bim(entry)` im Eigenschaften-Panel → `_bimSection`: aufklappbare Abschnitte IFC (Klasse, Name, GlobalId, Typ, Kennung …), Material (Schichten mit Dicke), Psets und Mengen (m/m²/m³ – SI angenommen), je Element gecacht, Auf-/Zu-Zustand je Modell gemerkt; scrollt ab 40 dvh. IFC-Strings (`\X\E4`, `\X2\…\X0\`) dekodiert (`decodeIfc`). Geprüft headless mit zwei Revit-IFC2X3 (IFC-Modell 10 MB – 2194 Elemente, 360 000 Dreiecke, ~1,5 s + BVH 0,2 s; Wohn-/Geschäftshaus 8,5 MB – 898 Elemente). Web-ifc meldet einzelne nicht triangulierbare Brep-Flächen („No basis found for brep“, ~50 von 20 000; Log aus). Mehrere IFC eines Projekts (Architektur/Tragwerk/TGA) liegen in denselben Koordinaten: Worker liefert `origin` (Verschiebung von `GetCoordinationMatrix`, Meter; Ausgabe = origin + (x, z, −y) des IFC-Weltpunkts, geprüft an einer Stütze), `root.userData.ifcOrigin`; ein IFC-Zusatzmodell neben einem IFC wird nicht daneben gestellt, sondern relativ zum ersten IFC-Modell (`ifcReference()`) exakt platziert. Knoten tragen `ifc.guid` (GlobalId).
- BCF-Tickets (`src/scripts/bcf/`, Okt. 2026): `.bcfzip`/`.bcf` per Drop (auch zusammen mit Modellen) oder Knopf mit Sprechblase in der Szene-Gruppe → Fenster rechts (`bcf-panel.js`, über dem Material-Panel, erst bei Bedarf geladen): Liste (Screenshot, #Index, Titel, Status · Priorität · Zuständig, Labels, Kommentarzahl; geschlossen/erledigt durchgestrichen), Klick = Detail + erste Ansicht anwenden; Detail: Titel, Status/Typ/Priorität/Zuständig (Freitext + Vorschläge aus Datei und BCF-Standardwerten), Fällig, Labels (Komma), Beschreibung, Ansichten (Klick = anwenden, ✕ = löschen, „+ Aktuelle Ansicht“), Kommentare (+ optional mit aktueller Ansicht), Ticket löschen; „Neu“ = Ticket mit aktueller Ansicht; Autor je Browser in den Einstellungen → BIM (`setup.addSection('bim')`, localStorage `rindr.bcf.author`, Event `rindr:bcf-author`; Fußzeile des Fensters zeigt „Als …“ bzw. „Autor festlegen …“ → öffnet die Seite; ohne Autor wird „Anonym“/„Anonymous“ eingetragen); Knopf nur sichtbar mit geladenem IFC-Modell oder geöffneter BCF (`updateBcfTool`, über `bcfUi.update` aus `refreshSceneGraph` – der läuft schon beim Start, bevor der Knopf existiert); „Speichern…“ (gelb bei Änderungen) per `showSaveFilePicker`, sonst Download; ungespeichertes ersetzen fragt nach. `bcf-format.js`: liest BCF 2.0 (flache `Component`-Liste mit Selected/Visible/Color, Viewpoint ohne Eintrag im Markup), 2.1 und 3.0 (Selection, Visibility DefaultVisibility + Exceptions, Coloring, Kommentare im Topic, `<Labels><Label>`), schreibt **BCF 2.1** (Zip ohne Kompression, `crc32` aus png-encode.js; `readZip(buffer, { paths: true })` für volle Pfade – vorher nur Dateinamen, je Ordner `markup.bcf` kollidierten). Viewer (`applyBcfViewpoint`/`captureBcfViewpoint`/`saveBcf`): BCF-Kamera in IFC-Weltkoordinaten (Meter, z oben) über das erste IFC-Modell (`ifcToWorld`/`worldToIfc`), Ziel = Kamerapunkt + Richtung × Abstand zur Szenenmitte (mind. 2 m), orthogonale Kamera → 30° perspektivisch im passenden Abstand, Up-Vektor ignoriert (OrbitControls); Sichtbarkeit nur für IFC-Elemente (nicht Geschosse/Klassengruppen) über `sceneGraph.setVisible` (rückgängig machbar), Auswahl per `selectObjects`; Meldung, wenn keines der Bauteile im Modell ist. Aufnahme: Kamera, Auswahl (auch alles in einem gewählten Geschoss/einer Klassengruppe), ausgeblendete IFC-Elemente als Exceptions, Screenshot ≤ 1600 px (`exportFrame`, ohne Gizmo/Hervorhebung); beim Speichern Header = geladene IFC-Dateien (Projekt-GlobalId + Name). Speichern mit BIM (`bimActive()`: IFC geladen oder Tickets offen): der normale Knopf „Szene speichern“ und „Speichern…“ im Ticket-Fenster schreiben **eine** `.bcfzip` mit Tickets + unserer Szene als Zusatzdatei `rindr.scene.json` im Zip-Wurzelordner (`SCENE_FILE`; andere BCF-Programme lesen nur bcf.version/project.bcfp/Ticket-Ordner und ignorieren sie; ohne Tickets ist es eine BCF ohne Topics); Name merkt sich `sceneFileName`. Ohne BIM weiter `.scene.json`. Öffnen (Drop oder „Szene laden“, Dialog nimmt jetzt auch .bcfzip): `openBcfFile(file, files)` – mit Szene wie `openSceneFile` (Modelle aus abgelegten Dateien/Server, fehlende ins Asset-Fenster); fremde BCF mit Dateinamen im Ticket-Kopf (`header[].filename`, Pfad abgeschnitten) → `addBcfModels`: nicht geladene IFC (Name oder Projekt-GlobalId) werden **hinzugefügt** (nie ersetzt) bzw. als fehlend gelistet; ohne Kopf (fremde Beispieldatei) nur Tickets, mit abgelegte Modelle laden normal. Geprüft headless: eigene .bcfzip in leerem Viewer → Modell vom Server, Kamera + Ticket zurück; fremde mit „C:\…\<Modell>.ifc“ + „Fehlt.ifc“ → Zusatzmodell geladen, Fehlt.ifc im Asset-Fenster. Tickets gehören zur Szene: Ersetzen (Splat-Drop, „Modelle ersetzen“, normale Szene per Drop/„Szene laden“) schließt sie (`closeBcf` → `bcfPanel.clear()`, ohne Rückfrage), Hinzufügen behält sie; bewusst nicht in `openModel` (das nutzt auch das Nachrücken eines Zusatzmodells und das Öffnen einer eigenen .bcfzip). Nicht umgesetzt: Einfärben (Coloring) und Schnittebenen der Viewpoints, Linien/Bitmaps, BCF-API (Server). Geprüft headless: fremde Beispieldatei (BCF 2.0, 23 Tickets, gehört zu einem anderen Projekt – Kamera fliegt dorthin, Meldung „nicht vorhanden“) → Speichern als 2.1 → Einlesen: Tickets/Kommentare/Screenshots/Auswahlen vollständig; eigenes Ticket am IFC-Modell: Kamera nach Datei-Rundlauf 0 mm / 0° Abweichung, Auswahl und ausgeblendete Türen wiederhergestellt. Echte Gegenprobe in BIMcollab/Solibri/Revit vom Nutzer zu prüfen.
