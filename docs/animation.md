# Animation und Morph Targets

`src/scripts/animation.js`.

- Morph Targets (Blendshapes): Meshes mit `morphAttributes.position` sind immer „posed“, der Importer liefert `result.animation` auch ohne Clips (Puppe bleibt). `ModelAnimation.morphs` (Name → Meshes, gleiche Namen mehrerer Meshes = ein Regler), `setMorph`/`getMorph`/`morphValues`/`setMorphs`. Scene Graph: Modell-Zeile mit Regler-Symbol (`morphs` = Anzahl, `refreshSceneGraph`). Eigenschaften (Modell oder Bauteil mit solchen Meshes): Abschnitt „Morph Targets“ mit Regler 0–1 je Form + „Alle auf 0“ (`morphApi` in viewer.js): Ziehen = Puppe live (GPU), Loslassen = einmal einbacken (`settle({ morphsOnly })`: nur Meshes, die eine Form tatsächlich bewegt – `_morphAffected`, gecacht; 3 s → 0,3 s), ein Rückgängig-Schritt je Regler (`mergeKey`). Szenen-Zustand je Modell `morphs: { Name: Wert }` (`setModelMorphs`). Abspielleiste/Leertaste/Zeitleiste nur für Modelle mit Clips (`clipAnims()`). Szenen-Zustand je Modell `animation: { clip, time }` (`animState`/`setModelAnimation`). Morph-Normalen werden nicht eingerechnet (Datei hat keine). Live-Puppe: `mergeGroups` (animation.js) ordnet den Index der Original-Geometrie nach Material und macht eine Zeichengruppe je Material – vorher eine Zeichengruppe je FBX-Gruppe (bei zehntausenden Gruppen > 100 000 Draw-Calls je Bild → Regler zäh). Erster Live-Zug einmalig langsamer (Morph-Textur + Shader). FBX nennen Texturen oft nur per Dateiname – per `?model=` aus einem Unterordner dann nicht gefunden (Ordner ablegen geht).
- Animation (`animation.js`, animierte glTF/FBX): Importer behält bei Dateien mit Clips das Loader-Objekt als „Puppe“ (`result.animation = { root, clips, scale, links }`, je Mesh-Eintrag Quell-Mesh/Instanz/posed + `sourceVertex` = eigener → Quell-Vertex). `ModelAnimation`: `AnimationMixer` auf der Puppe, je Bild `apply()`: Mesh-Matrix = Skalierung · Quell-`matrixWorld` (Knoten-Animation), verformte Meshes (Skinning/Morph): beim Abspielen/Ziehen wird das `SkinnedMesh` der Puppe selbst gezeigt (GPU-Skinning wie Sketchfab; Puppe in einem Container mit Skalierung → mm unter der Modell-Wurzel, mit unseren Materialien, unsere gebackenen Meshes so lange ausgeblendet – `startLive`/`stopLive`), erst bei Pause einmal per CPU in unsere Meshes übernommen (`getVertexPosition` + Normalen über `applyBoneTransform`). Vorher CPU-Skinning + kompletter Upload jedes Bild → stark ruckelnd. Kontaktschatten und Zeitanzeige beim Abspielen nur ~10×/s. Play/Pause-Symbol nur bei echtem Zustandswechsel setzen – das Neusetzen alle 100 ms tauschte das Element zwischen Maus-Drücken und -Loslassen → Klick auf Pause ging verloren. Live-Teile folgen Bauteil-Verschiebungen/Drehungen/Explosion (`_followParts`: X = Bewegung der Bauteil-Gruppe in Weltkoordinaten = Wurzel · (Wurzel⁻¹ · Gruppe) · Wurzel⁻¹, je Bild; überschriebenes `updateMatrixWorld` der Puppen-Meshes multipliziert X nach three.js' eigener Berechnung auf `bindMatrixInverse` (Skinning, attached: Ergebnis = matrixWorld · bindMatrixInverse · S) bzw. vor `matrixWorld` (nur Morph) – DetachedBindMode geht nicht, setzt bindMatrixInverse jedes Bild neu; geprüft: Vertex live = Vertex nach Pause, Abstand 0 bei verschobener + gedrehter Gruppe; vorher sprang das Teil beim Abspielen an die Originalposition). Laden/Hinzuladen pausiert die Animation (`stopAnimation`) – die Puppe darf dabei nicht in der Szene hängen. Puppen-Meshes können Material-Arrays haben (kein `userData`) → alle Zugriffe `material?.userData?.materialId` (vorher „Cannot read properties of undefined (reading 'materialId')“ beim Hinzuladen während der Wiedergabe). Abspielleiste `#playbar` über der unteren Leiste (nur mit Animation): Play/Pause (auch Leertaste), Zeitregler, Zeit, Clip-Auswahl bei mehreren Clips; alle animierten Modelle (auch Zusatzmodelle) teilen eine Zeitleiste (neu hinzugefügte springen auf die aktuelle Zeit – `addAnimation`; vorher Start bei 0 → versetzt; Clips unterschiedlicher Länge schleifen je für sich). Abspielen in HQ schaltet auf Default (`hqBeforePlay`), Pause schaltet zurück auf HQ; HQ während der Wiedergabe pausiert zuerst (vorher: Zoomen/Drehen weckte den Pathtracer, die Animation lief unsichtbar weiter). Beim Abspielen/Ziehen nur Raster (`pauseForEdit`), danach `settleAnimation`: Bounding-Boxen neu, `boundsTree` verworfen, bei Verformung neue Pathtracing-Szene. Picking (Hover, Material-Drag, Klick) trifft nie die Puppe (`mesh.raycast = () => {}` – `SkinnedMesh.raycast` skinnt jeden Punkt auf der CPU, Zehntel-Sekunden je Strahl → Ruckeln beim Material-Ziehen während der Wiedergabe), sondern unsere ausgeblendeten Meshes (`userData.liveHidden`, `isShown` lässt sie zu; Pose vom letzten Einbacken): 0,3 ms. `dragover` pickt nur bei geänderter Zeigerposition/Alt (`dragPick`). Clip + Zeitpunkt im Szenen-Zustand (siehe Morph Targets); Tangenten verformter Meshes bleiben vom Import.
