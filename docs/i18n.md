# Sprache / i18n

Oberflächentexte, Sprachdateien, Prüfskript.

- **Sprache / i18n:** Code (Bezeichner, Kommentare, Konsolen-Ausgaben, PHP) ist komplett englisch; alle Oberflächentexte kommen aus `src/i18n/<sprache>.json` (Referenz: `de_de.json`, ~620 Schlüssel, verschachtelt; dazu `en_us.json` – Begriffe: Körper = solid, Bauteil = part, Flächengruppe = surface group, Strg = Ctrl; bei neuen Schlüsseln immer beide Dateien pflegen, Gleichstand von Schlüsseln/Platzhaltern prüfen). `src/scripts/i18n.js`: `t('bereich.schlüssel', { platzhalter })`, Mehrzahl als `{ one, other }` (über `count`), `getLocale()` für Zahlen/Datum, `applyDom()` für `data-i18n` / `data-i18n-title` / `data-i18n-placeholder` sowie `data-i18n-html` (nur `<strong> <b> <em> <i> <br>` ohne Attribute, Rest als Text – `formatHtml`, auch beim Build in index.astro per `set:html`; z.B. Schriftzug unten links `page.brand`, davor das Logo `src/assets/rindr.svg` als Astro-SVG-Komponente (`import Logo from '../assets/rindr.svg'`), Datei unverändert wie exportiert (schwarze Flächen, weiße Details); weiß per SVG-Filter `#logo-white` (verstecktes `<svg>` in index.astro, `feColorMatrix`: Farbe = Weiß, Alpha = Alpha − Leuchtdichte → Schwarz wird deckend weiß, Weiß durchsichtig) + `drop-shadow` (`[filter:url(#logo-white)_drop-shadow(…)]`); `brightness-0 invert` machte auch die Details weiß; Seitentitel `<title data-i18n="page.title">`; Meta-Description + Open Graph/Twitter-Tags aus `page.description`/`page.title`/`page.ogImageAlt` – nur Deutsch, Crawler führen kein JS aus; Vorschaubild `public/og-image.png` 1200×630, erzeugt per ImageMagick aus dem weiß eingefärbten Logo; absolute `og:image`/`og:url` nur mit `SITE_URL` (`.env`)) (index.astro rendert Deutsch schon im Build, `tr()` im Frontmatter). Sprachwahl: `?lang=` > gespeicherte Wahl (`setLanguage`, localStorage) > Browsersprache > de_de; fehlende Schlüssel fallen auf de_de zurück (mit `?debug` Konsolen-Warnung „[i18n] missing key“). Neue Sprache = neue JSON-Datei in `src/i18n/` + `npm run build` (per `import.meta.glob` eingebunden). Konstanten mit Beschriftungen speichern Schlüssel, übersetzt wird beim Anzeigen. Nicht übersetzt: Konsolen-Ausgaben, Fehlermeldungen der Worker (STEP-Kern, HDR – englischer Klartext), gespeicherte Werte/IDs. KI-Fehler sind `KiError` mit `code`/`params` (englische Meldung), `ki-render.js` zeigt `ki.errors.<code>`; auch der KI-Prompt kommt aus der Sprachdatei (`ki.prompt.*`). Gespeicherte deutsche Werte migriert: Qualitätsstufen jetzt `coarse/medium/fine/veryFine` (`normalizeQuality` liest alte Szenen mit Grob/Mittel/Fein/Sehr fein). Unbenannte STEP-Knoten: Worker liefert `autoName`, Name wird im Hauptprogramm übersetzt. Prüfskript: Scratchpad `i18n-check.mjs` (`keys` = verwendete Schlüssel vorhanden?, `german` = deutsche Reste im Code).
