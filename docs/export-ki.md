# Bild-Export und KI-Rendering

`image-export.js`, `png-encode.js`, `ki-render.js`, `ki-gemini.js`.

- KI-Rendering (Fenster ohne Vollflächen-Abdunklung, Panel-Stil `bg-black/60` + Blur wie Einstellungen, ✕ / Esc / Klick daneben schließt): Knopf „KI“ neben HQ (`viewModeBar.addAction`, erzwingt kein HQ) → `ki-render.js`: aktuelle Darstellung (Default/Basic sofort, HQ: auf Phase `done` warten, `waitForImage`), Bild ohne Schärfeebene/Hervorhebung/Gizmo aufnehmen (`captureRequest` im Render-Loop, `toDataURL` im selben Task wie das Rendern), Dialog mit Prompt aus `buildPrompt` (Materialien der sichtbaren Meshes: Name, Farbe, `describeMaterial`, bis 6 Bauteilnamen; unbenannte STEP-Farben als „CAD-Material in #…“; Umgebung/HDRI) – bearbeitbar, Auflösung 1K/2K/4K – → Gemini direkt aus dem Browser (`ki-gemini.js`, Interactions-API `KI.endpoint`, Header `x-goog-api-key`, Google erlaubt CORS – auch unter COEP) → Vorher/Nachher-Schieber, Herunterladen (Blob-URL), „Neu erzeugen“ (`force`), Verlauf, Löschen (mit Rückfrage). Eigener API-Schlüssel des Nutzers: Einstellungen → „KI-Rendering“ (`setup.addSection('ki')`: Schlüssel-Feld `text(…, { mask })` zeigt nur `••••••••` + letzte 4 Zeichen und leert sich beim Hineinklicken, „Schlüssel entfernen“, Modell, Standard-Auflösung, Hinweis auf localStorage-Risiko + Link zu AI Studio); gespeichert in localStorage `rindr.ki.apiKey/model/size` (`kiSettings`); ohne Schlüssel zeigt der KI-Knopf einen Hinweis mit „Einstellungen öffnen“ (`ctx.openSettings`). Verlauf + Zwischenspeicher in IndexedDB `rindr-ki` / Store `renders` (Eingabe- und Ergebnisbild als Blob, id = Hash aus Modell/Größe/Format/Anweisung/Prompt/Bild → gleiche Anfrage ohne neuen Aufruf), nur in diesem Browser. Antwort: Bildsuche in `steps[].content[]`/`output_image`/`inlineData`, bei 400 wegen `response_format` einmal ohne; 400 „API key“/401/403 → `INVALID_API_KEY`; Zeitlimit 240 s. Voreinstellungen `KI` in config.js (Endpunkt, Modell `gemini-nano-banana-2.1`, Größen, Link). Feste Anweisung (englisch, `SYSTEM_INSTRUCTION`): Bildaufbau/Geometrie/Farben beibehalten, nur Fotorealismus. Früher (bis Okt. 2026) PHP-Vermittler `server/ki.php` + `public/api/*.php` + `.env` (Schlüssel auf dem Server, Ratenbegrenzung, Ablage `storage/ki/`) – entfernt, liegt in der Git-Historie. Geprüft mit nachgebildeter Gemini-Antwort (puppeteer, Scratchpad `ki.mjs`: falscher Schlüssel → Meldung, richtiger → Ergebnis, erneut → Zwischenspeicher, Verlauf); echter Gemini-Aufruf vom Nutzer zu testen.
- Bild-Export (`image-export.js`, Knopf mit Bild-Symbol in der Szene-Gruppe der Leiste): PNG (optional transparenter Hintergrund – dann immer vormultipliziertes Alpha, mit Schwarz) oder JPG (Qualität 0,92) in Canvas-Auflösung der aktuellen Ansicht; HQ wartet auf das fertige Bild (`waitForImage`, gemeinsam mit KI); Speichern immer direkt als Download (ein „Speichern unter“-Dialog geht nur direkt nach dem Klick – in HQ wird erst gewartet, dann lehnte der Browser ab und lud doch herunter); Name = Szenen- bzw. Modellname; Bild ohne Gizmo/Hervorhebung/Schärfelinie (`exportFrame` im Render-Loop). Transparenz = Triangulation Matting (`exportImage`/`composeMatte` in viewer.js): dieselbe Ansicht vor schwarzem und grauem Hintergrund (`environment.matte` = `THREE.Color` – der Pathtracer hat dafür einen eigenen 8-Bit-Farbweg; eine eigene Float/Half-Float-Textur erzeugte eine Shader-Variante mit „unresolved value …_sampler“; Grau auf 8 Bit gerundet; Licht/HDRI/Spiegelungen/Schattenfänger bleiben), Alpha = 1 − (grau − schwarz)/Grauwert je Kanal **vor dem Tonemapping** (8-Bit-sRGB → linear → ACES-Fit invertiert `acesFitInverse`, Grauwert vor dem Fit 0,6), 1,5 % Toleranz an beiden Enden; Farbe = Bild vor Schwarz (vormultipliziert). Erfasst damit Tiefenschärfe-Ränder, Glas, Bodenschatten (Schattenfänger zeigt Hintergrund × Sichtbarkeit), Bloom/Glare/Farbsaum; das Rauschen ist in beiden Durchgängen gleich (stable noise) → Modelle bleiben deckend. Ausgabe nur premultiplied (Farbe = Schwarz-Bild, additiver Glow; Straight-Variante wieder entfernt). PNG wird selbst geschrieben (`png-encode.js`: Filter 0, zlib per `CompressionStream('deflate')`, CRC32) – ein Canvas speichert intern vormultipliziert und verlöre die Farbe von Glow-Pixeln mit Alpha 0. HQ = zwei volle Durchgänge (doppelte Zeit), Bildschirm zeigt währenddessen schwarz/grau. Erster Ansatz (Raster-Masken + Bild/Hintergrund-Verhältnis) verworfen: scharfe Maske ohne Tiefenschärfe/Bloom. Größe 1×–4× der Canvas-Auflösung (`exportImage(…, scale)`): Pixel-Ratio des Renderers wird erhöht (CSS-Größe bleibt, Bildschirm zeigt das große Bild verkleinert), Raster/Pathtracer rechnen in der Größe (PT startet bei Größenänderung selbst neu), danach zurück; Effekte behalten den Bildschirm-Look (`lens.setPixelScale`: Glare/Flare/God-Rays-Targets relativ zur Bildschirm-Version, Bloom `setResolutionScale(0,5/scale)`); Grenze `maxExportSize` = GPU-Limit, höchstens 8192 px je Seite (größere Faktoren im Dialog ausgegraut). Transparenz mit Bildlook: Alpha-Aufnahmen mit ACES + neutralem Look (`captureNeutral`, nur die Ausgabe ändert sich), Farbe = Schwarz-Durchgang mit Look. Geprüft: Raster 2× transparent (1400×900); HQ 2× vom Nutzer zu testen.
